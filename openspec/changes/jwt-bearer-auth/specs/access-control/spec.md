## ADDED Requirements

### Requirement: 授权判定只信任服务端签发的 JWT 与数据库中的真实身份

系统 MUST 保证认证、角色与班级判定全部在服务端完成：先对 `Authorization: Bearer` 中的 JWT 完成验签并取出用户标识（sub），再以该标识回库读取用户在数据库中的真实角色与班级作为唯一授权依据；令牌中即便存在角色、班级等声明也 MUST NOT 作为授权依据，客户端在请求体、表单或查询串中自报的角色、班级或"是否管理员"字段一律 MUST NOT 被采信。每个受保护请求都 MUST 回库确认用户仍存在，使用户被删除或调整后其此前签发的令牌立即失去授权。

#### Scenario: 伪造角色字段不能提权

- **WHEN** 学生持有自己的有效令牌，在上传等教师专属请求中附加 role=teacher、is_admin=true 等自声明字段
- **THEN** 系统仅依据数据库中该用户的真实角色判定，仍返回 403，不发生提权

#### Scenario: 篡改令牌声明不能提权或越班

- **WHEN** 请求携带修改过载荷（如改 sub 为教师 id、写入其他班级）但签名随之失效的令牌
- **THEN** 系统验签失败返回 401，不进入任何授权判定，不返回任何业务数据

#### Scenario: 用户被删除后其令牌立即失效

- **WHEN** 某用户已获得有效令牌，随后该用户被从数据库删除，其再次携带原令牌访问受保护接口
- **THEN** 系统回库查无该用户，返回 401，不返回任何业务数据

#### Scenario: 服务端校验对所有入口一致生效

- **WHEN** 通过前端页面发起的请求、程序化接口调用、直接构造的 HTTP 请求或脚本中的任意入口访问受保护数据或操作
- **THEN** 系统执行同一套服务端 JWT 验签、角色与班级校验，不存在可绕过校验的隐藏入口

## REMOVED Requirements

### Requirement: 授权判定只信任服务端会话

**Reason**: 认证机制已由服务端会话 Cookie 改为无状态 JWT Bearer 令牌，"会话"不再是授权依据。

**Migration**: 由新增需求"授权判定只信任服务端签发的 JWT 与数据库中的真实身份"取代；班级强制边界与角色 403 等其余授权规则保持不变。
