## MODIFIED Requirements

### Requirement: 本班材料列表可查且包含新上传记录

系统 MUST 为携带有效令牌的已登录用户提供其所属班级材料的 JSON 列表接口（前端页面外壳通过该接口取数并在浏览器端渲染）；教师成功上传后，该记录 MUST 立即出现在本班列表中，且 MUST NOT 出现在其他班级的列表中。列表每条至少包含材料标识、文件名、类型、大小、上传者与上传时间，按上传时间倒序排列；服务端 MUST NOT 在未鉴权的 HTML 响应中直接输出材料数据。

#### Scenario: 查看本班材料列表

- **WHEN** 已登录用户的前端携带 Bearer 令牌请求材料列表接口
- **THEN** 系统返回 JSON 形式的本班材料记录，每条含材料标识、文件名、类型、大小、上传者姓名与上传时间，按上传时间倒序排列

#### Scenario: 上传后本班列表立即可查

- **WHEN** 教师成功上传一个材料后立即请求本班材料列表接口
- **THEN** 返回结果中包含该新材料，文件名、大小、上传者与所属班级与上传时一致

#### Scenario: 新上传材料对其他班级不可见

- **WHEN** B 班教师上传材料后，A 班任意用户携带自己的令牌请求材料列表接口
- **THEN** A 班返回结果中不包含该材料（班级过滤由 access-control 定义）

#### Scenario: 未携带令牌取不到列表数据

- **WHEN** 未认证请求直接访问材料列表接口
- **THEN** 系统返回 401 JSON，不返回任何材料记录

### Requirement: 材料文件下载

系统 MUST 允许本班已登录用户凭有效 Bearer 令牌下载材料的原始文件内容；下载响应与对应元数据记录一致。浏览器前端 MUST 通过在请求中附加 Authorization 头的方式获取文件（下载不再依赖 Cookie 或可公开访问的地址）。

#### Scenario: 本班用户下载材料

- **WHEN** 本班教师或学生携带有效令牌请求下载一条本班材料
- **THEN** 系统返回该材料的原始文件内容，下载文件名与内容类型和上传时一致

#### Scenario: 未携带令牌的下载请求被拒绝

- **WHEN** 请求下载材料时未携带有效令牌（包括直接在浏览器地址栏输入下载地址）
- **THEN** 系统返回 401，不返回该文件的任何字节

#### Scenario: 数据库记录存在但物理文件缺失

- **WHEN** 某条材料元数据存在但其物理文件在存储目录中不可用
- **THEN** 系统返回明确的服务端错误（5xx），不得返回损坏或张冠李戴的文件内容

### Requirement: 材料元数据完整性

每条材料记录 MUST 包含文件原始名、服务端存储键、内容类型、字节大小、上传者、所属班级与创建时间；上传者、所属班级与创建时间 MUST 由服务端根据已认证令牌对应的用户与服务器时钟确定，请求中自报的身份或班级字段不得影响这些值。

#### Scenario: 元数据字段完整且归属正确

- **WHEN** 教师成功上传一个材料
- **THEN** 数据库记录包含上述全部字段，其中上传者为该令牌所对应用户本人、所属班级为该用户所在班级、创建时间由服务端生成
