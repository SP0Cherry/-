## MODIFIED Requirements

### Requirement: 健康检查接口

系统 MUST 提供无需认证的 `GET /health` 接口，用于容器编排与课堂环境自检；接口 MUST 反映应用与数据库依赖的真实可用性。

#### Scenario: 应用与数据库正常

- **WHEN** 在应用正常运行、数据库可访问时请求 `GET /health`（不携带 Authorization 头）
- **THEN** 系统返回 200 与表明健康的 JSON 状态体，且该请求不触发 401 或登录跳转

#### Scenario: 数据库不可用时告警

- **WHEN** 应用进程存活但数据库无法访问时请求 `GET /health`
- **THEN** 系统返回 503 与表明依赖异常的 JSON，而不是仍返回健康

### Requirement: 密钥与配置只来自服务端环境变量

系统 MUST 只从服务端环境变量（或服务端读取、不提交仓库的环境文件）获取 JWT 签名密钥等敏感配置；密钥 MUST NOT 硬编码在源码中、MUST NOT 写入镜像、MUST NOT 出现在发给浏览器的任何内容里；访问令牌有效期等可配置项 MUST 同样由服务端配置提供默认值与环境变量覆盖途径。生产模式下缺少必要密钥时应用 MUST 拒绝启动。

#### Scenario: 缺少密钥时快速失败

- **WHEN** 应用以生产模式启动且未配置 JWT 签名密钥（或其复用的密钥环境变量）
- **THEN** 应用在启动阶段报错退出，不以弱默认密钥或空密钥继续运行

#### Scenario: 仓库与镜像不含真实密钥

- **WHEN** 检查代码仓库中的配置样例或构建出的容器镜像
- **THEN** 只能看到占位符（如 `.env.example` 中的说明性示例），不存在可用于签发或验证令牌的真实密钥
