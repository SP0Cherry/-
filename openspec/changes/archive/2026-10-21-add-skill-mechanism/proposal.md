## Why

当前知识问答只有“统一助教”一种行为，无法按学科教学法约束回答方式，也不能把本班已登记的 MCP 工具接入问答流程。教师需要为本班预置“数学解题引导”“语文解题引导”这类技能，让学生提问时选择使用；学生需要看到技能是否命中、MCP 工具是否真的被调用，而不是得到无法解释的结果。

## What Changes

- 新增班级级**技能（Skill）**能力：教师上传/删除本班技能，学生提问时可勾选使用哪些技能。
- 技能文件采用 SKILL.md 文本格式：首个空行前是元数据，之后是引导规程；支持字段 `名称`、`适用条件`、`资料`、`工具`、`启用`。
- 提交时校验：文件不超过 8000 字；`名称`、`适用条件`、`启用` 必填；空行后必须有正文；重复字段、未定义字段一律拒绝，并返回面向教师的可读中文错误。
- `工具` 字段同时支持内置 `knowledge_search` 与 MCP 引用 `工具名@服务器名`（如 `formula_hint@campus-tools`）。
- 保存技能时校验 MCP 引用：服务器必须属于本班、已连接，且该工具已通过 `tools/list` 进入缓存；否则拒绝保存。
- 学生提问命中带 MCP 工具的技能时，服务端使用服务端保存的令牌调用远端 `tools/call`；工具结果作为**数据**拼入用户消息，绝不作为系统指令。
- **BREAKING**：`POST /api/kb/ask` 由一次性 JSON 改为 SSE 流式响应。首个 `meta` 事件包含技能命中与 `tool_calls`（工具引用、状态 `ok`/`denied`/`error`）；随后推送回答增量与结束事件。未连接或越权调用必须记为 `denied`，不得静默成功。
- 为 A 班预置两份示例技能（数学解题引导、语文解题引导），随幂等种子初始化写入。
- 继续沿用第 3–5 课约束：班级只取自登录会话、跨班访问统一 404、所有接口 Bearer 鉴权；技能管理与 MCP 引用仍按教师/学生角色授权。

## Capabilities

### New Capabilities

- `qa-skills`: 班级技能的 SKILL.md 解析、教师管理、提问时选择与命中规则、MCP 工具引用校验、服务端工具调用与结果数据化拼装。
- `knowledge-qa`: 班级知识问答的流式响应契约，包括 SSE `meta`（含技能与 `tool_calls` 状态）、回答增量、结束/错误事件，以及既有检索与“无资料继续提问”门控行为。

### Modified Capabilities

- `access-control`: 将班级强制边界与教师专属授权从材料扩展到技能、技能工具引用及 MCP 工具调用；跨班技能/服务器一律 404。
- `app-foundations`: 演示种子数据在 A 班原有材料之外，新增两份预置技能，且重复执行保持幂等。

## Impact

- 数据模型：新增班级级 `Skill` 表（名称、适用条件、资料、工具引用、正文、启用、创建者/时间），与 `McpServer` 建立班级级引用关系。
- 后端：新增技能解析/校验/服务与教师管理 API；`app/kb/service.py` 增加技能命中与 MCP 工具执行；`app/kb/routes.py` 的 `/api/kb/ask` 改为 SSE；`app/kb/llm.py` 增加流式生成接口；`app/seed.py` 预置 A 班技能。
- 前端：`kb.html`/`kb.js` 增加技能勾选、流式渲染与 `tool_calls` 状态展示；教师端增加技能上传/删除入口与可读错误提示。
- 兼容性：`POST /api/kb/ask` 的 JSON 契约被 SSE 取代，现有调用方与测试需同步迁移；`/api/kb/search`、材料与 MCP 服务器管理接口不受影响。
- 安全：MCP 令牌继续只保存在服务端；工具输出只作为数据进入用户消息，不能改变系统规程。
- 依赖：复用现有 `MCPClient` 与 Compose 内自建 MCP 服务，不引入新的外部服务。
