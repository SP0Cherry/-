# Delta Spec: access-control

## Purpose

在服务端强制执行基于角色（教师/学生）的功能授权与基于班级的数据边界：学生无法调用教师专属操作，任何用户都无法读取或操作其他班级的数据，且这些保证不依赖前端界面隐藏，也不信任请求中自报的角色或班级。

## ADDED Requirements

### Requirement: 教师专属操作的角色授权

系统 MUST 在服务端对教师专属操作（本期为教学材料上传）进行角色校验：仅教师角色可以执行；学生角色即使绕过界面直接调用接口也 MUST 被拒绝（403）。

#### Scenario: 教师执行上传操作

- **WHEN** 已登录的教师调用材料上传接口并通过文件校验
- **THEN** 系统允许该操作继续执行

#### Scenario: 学生直接调用上传接口返回 403

- **WHEN** 已登录的学生绕过前端、直接向材料上传接口发起请求（即使请求格式与文件完全合法）
- **THEN** 系统返回 403 禁止访问，不保存任何文件、不写入任何材料记录

#### Scenario: 界面前置差异不影响授权结果

- **WHEN** 学生使用 curl/Postman/脚本等工具以与教师完全相同的 HTTP 请求直接调用上传接口
- **THEN** 服务端独立完成角色判定并返回 403，授权结果不取决于前端页面是否显示上传入口

### Requirement: 班级是材料数据的强制边界

系统 MUST 以当前登录用户所属班级作为材料数据（列表、详情、下载、上传归属）的服务端强制边界：用户只能看到和操作本班数据；任何来自请求参数、表单或查询串中的班级标识都 MUST NOT 能扩大该边界。

#### Scenario: 材料列表服务端按本班过滤

- **WHEN** 用户请求材料列表
- **THEN** 系统仅返回与其所属班级一致的材料记录；即使数据库中存在其他班级的材料，也不返回任何其他班级的记录

#### Scenario: 跨班访问材料详情被拒绝

- **WHEN** A 班用户通过直接输入 URL 或构造请求的方式访问 B 班某条材料的详情
- **THEN** 系统返回 404，不返回该材料的任何字段，也不确认该材料是否存在

#### Scenario: 跨班下载材料被拒绝

- **WHEN** A 班用户直接请求 B 班某条材料的下载地址
- **THEN** 系统返回 404，不返回该文件的任何字节

#### Scenario: 上传的材料强制归属上传者所在班级

- **WHEN** 教师上传材料时在请求中额外传入其他班级标识（隐藏表单字段、查询参数或请求体字段）
- **THEN** 系统忽略该伪造标识，材料必须且只能归属该教师所属班级

### Requirement: 授权判定只信任服务端会话

系统 MUST 保证认证、角色与班级判定全部在服务端完成并基于服务端会话对应用户在数据库中的真实身份；客户端提交的角色、班级或"是否管理员"等自声明字段一律 MUST NOT 作为授权依据。

#### Scenario: 伪造角色字段不能提权

- **WHEN** 学生在上传请求中附加 role=teacher、is_admin=true 等自声明字段
- **THEN** 系统仅依据会话对应用户的真实角色判定，仍返回 403，不发生提权

#### Scenario: 服务端校验对所有入口一致生效

- **WHEN** 通过页面、表单提交、接口、直接 URL 或脚本中的任意入口访问受保护数据或操作
- **THEN** 系统执行同一套服务端认证/角色/班级校验，不存在可绕过校验的隐藏入口
