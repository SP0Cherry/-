## Why

CampusClaw 是一个用于教学的网站，需要从零搭建。本期先建立安全地基：教师与学生凭账号密码登录，教师可把教学材料上传进本班知识库，学生只能浏览本班材料。认证、角色授权与班级数据隔离必须全部在服务端强制执行，使本站成为"前端隐藏 ≠ 安全"的正面教学范例；同时提供 Docker Compose 一键启动与健康检查，保证课堂环境快速可复现。

## What Changes

- 新建 Flask 应用（应用工厂 + Blueprint + Jinja2 服务端渲染），数据层使用 SQLAlchemy + SQLite。
- 账号密码**自助注册**：用户名唯一，注册时选择角色（教师/学生）与已有班级；**密码必须加盐哈希存储，严禁明文落库、写日志或出现在任何响应中**。
- 登录/登出与服务端签名会话：会话 Cookie 设 httpOnly、SameSite=Lax；**会话签名密钥只允许来自服务端环境变量**，不硬编码、不进镜像、不下发浏览器；生产模式缺少密钥时拒绝启动。
- 未登录访问受保护页面重定向到登录页（支持登录后回跳）；未登录调用受保护接口返回 401。
- **角色权限**：仅教师可上传材料；学生绕过前端直接调用上传接口时服务端返回 403，不留文件、不写记录。
- **班级隔离**：班级是强制数据边界，材料列表/详情/下载/上传归属全部在服务端按会话用户的班级过滤与校验；A 班访问 B 班材料返回 404，不泄露资源存在性；请求中伪造的班级或角色字段一律无效。
- **上传入库**：教师上传文件落服务端本地磁盘（服务端生成 UUID 存储键，不放在静态目录），元数据写入 SQLite；上传成功后本班材料列表立即能查到该记录，本班用户可下载。
- **预置数据**：提供幂等种子命令，预置 A 班、B 班及四个跨班演示账号（每班一名教师、一名学生）与 A 班示例材料。
- **运行与可观测**：应用提供无需登录的 `GET /health`（真实检查数据库可用性）；通过 Docker Compose 一条命令启动，SQLite 数据库文件与上传目录用卷持久化，容器重建后数据不丢。
- pytest 集成测试覆盖未登录重定向/401、学生上传 403、跨班访问 404、上传后本班列表可查等关键场景。

## Capabilities

### New Capabilities

- `user-auth`: 自助注册、密码加盐哈希、账号密码登录/登出、服务端签名会话，以及未认证访问受保护页面与接口时的重定向/拒绝。
- `access-control`: 服务端强制的角色授权（教师专属上传，学生 403）与班级数据边界（跨班 404），不信任任何客户端提交的角色/班级字段。
- `teaching-materials`: 教学材料的上传校验、本地磁盘持久化与元数据入库、本班材料列表查询与文件下载。
- `app-foundations`: 幂等预置数据、Docker Compose 容器化启动、`GET /health` 健康检查，以及密钥只来自服务端环境变量的配置管理。

### Modified Capabilities

无（项目首个变更，不存在既有 spec）。

## Non-goals（本课不做）

- **知识库检索问答**：不做基于材料内容的检索、语义搜索或 RAG 问答。
- **对话助手**：不做聊天机器人、AI 助教等任何对话式功能。
- **作业提交与批改**：不做学生提交作业、教师批阅、评分、反馈等流程。
- **SSO / 生产高可用**：不对接学校统一身份认证、OAuth、LDAP/AD 等单点登录；不做多副本、负载均衡、托管数据库、自动扩缩容等生产 HA 部署，仅提供单机 Docker Compose 教学部署。
- 管理员后台、账号审批、邀请码、邮箱验证、找回密码。
- 一个用户归属多个班级、跨班/换班管理（本期每人固定归属一个班级）。
- 材料在线预览、编辑、删除、版本管理；对象存储（S3/OSS）；文件病毒扫描。

## Impact

- **代码**：全新 Python/Flask 代码库（应用工厂、Blueprint、服务端鉴权装饰器、数据访问层、Jinja2 模板、CLI 种子命令、pytest 测试）。
- **数据**：SQLite 数据库（class / user / material 表，外键约束，`(class_id, created_at)` 索引）；受管理的本地上传目录（不放静态目录、加入 `.gitignore`）。
- **接口**：注册/登录/登出、材料列表页与上传/下载接口、`GET /health`。
- **依赖与运行**：Flask、Flask-SQLAlchemy（或 SQLAlchemy）、Werkzeug（密码哈希）、gunicorn、pytest；Docker 与 Docker Compose。
- **配置**：新增 `.env.example`（仅占位符）与环境变量 `SECRET_KEY`、`DATABASE_URL`（或 SQLite 路径）、上传目录等；真实密钥只存在服务端环境。
- **安全面**：凭据哈希存储、会话密钥管理、上传校验、越权（403）与跨班（404）访问，均为本期重点测试对象。
