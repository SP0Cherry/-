## Purpose

为课程项目的 MCP 与技能管理接口提供可浏览、可试调的 OpenAPI 3 文档，降低联调、课堂演示与后续维护成本，同时不泄露令牌等敏感信息、不改变既有接口语义。

## ADDED Requirements

### Requirement: 覆盖主要接口的 OpenAPI 3 文档

系统 MUST 提供一个可公开读取的 OpenAPI 3 文档端点，返回合法 JSON，至少覆盖以下操作：登录、MCP 服务器列表/登记/删除、连接、断开、缓存工具清单、手动工具调用、技能列表、技能上传、技能删除、MCP 工具调用审计查询。

每个操作 MUST 描述请求方法、路径、所需鉴权、关键请求参数或请求体、成功响应与主要错误响应（401、403、404、409 等）。技能上传 MUST 声明为 `multipart/form-data` 文件上传。MCP 工具调用与审计查询 MUST 声明 Bearer 鉴权；文档 MUST 包含可供 Swagger UI 使用的 Bearer 安全方案。

文档生成 MUST NOT 依赖外部网络或正在运行的 MCP 服务器，MUST NOT 包含真实令牌、服务器令牌、技能正文或数据库内容。

#### Scenario: 文档端点返回合法 OpenAPI 3 JSON

- **WHEN** 任意用户请求文档端点
- **THEN** 系统返回 200 与合法 OpenAPI 3 JSON，包含服务器登记、连接、工具调用、技能上传与审计查询等路径

#### Scenario: Bearer 安全方案可被发现

- **WHEN** 客户端读取文档
- **THEN** 文档中声明了 Bearer 鉴权方案，受保护操作引用了该方案

#### Scenario: 技能上传声明为文件上传

- **WHEN** 客户端读取技能上传操作的定义
- **THEN** 该操作声明 `multipart/form-data` 请求体并包含文件字段

#### Scenario: 文档生成不依赖外部系统

- **WHEN** MCP 服务器未运行或网络不可用时请求文档
- **THEN** 文档仍能正常生成并返回，不因 MCP 连接失败而报错

#### Scenario: 文档不含敏感信息

- **WHEN** 客户端读取文档全部内容
- **THEN** 响应中不出现任何真实服务器令牌、技能正文或工具返回数据

### Requirement: 浏览器可直接试调的 Swagger UI 页面

系统 MUST 提供一个可通过浏览器直接打开的 Swagger UI 页面，用于浏览上述文档并试调主要接口（至少连接服务器、查看工具、手动调用工具、保存/删除技能、查询审计）。

页面加载的脚本、样式与字体资源 MUST 全部同源且随应用分发，MUST NOT 依赖 CDN 或外部字体服务，以保证离线可用并符合现有的内容安全策略。页面 MUST 允许用户填入或授权 Bearer 令牌，使受保护接口的试调能够携带令牌；文档页面本身 MUST 可作为公开静态壳访问，但其中的业务请求 MUST 仍按既有鉴权与班级边界校验。

页面 MUST NOT 要求放宽其他业务页面的内容安全策略；如需为文档页单独放宽样式或脚本限制，MUST 仅作用于文档页与其静态资源。

#### Scenario: 浏览器打开文档页面

- **WHEN** 用户在浏览器访问文档页面
- **THEN** 页面正常渲染 Swagger UI，并列出主要接口分组

#### Scenario: 离线加载无外部依赖

- **WHEN** 在无法访问公网的环境中打开文档页面
- **THEN** 页面脚本、样式与字体均从同源加载成功，不出现外部域名请求

#### Scenario: 授权后试调受保护接口

- **WHEN** 用户在页面中填入有效 Bearer 令牌并试调连接服务器或查看工具
- **THEN** 请求携带该令牌，返回结果在页面中可见；未授权时试调返回 401

#### Scenario: 试调仍受角色与班级约束

- **WHEN** 学生令牌在文档页面试调技能上传或审计查询
- **THEN** 接口返回 403，页面展示该错误且不产生数据变更

#### Scenario: 文档页内容安全策略不外溢

- **WHEN** 浏览器加载登录、材料或问答等业务页面
- **THEN** 这些页面继续使用原有的严格内容安全策略，未因文档页而放宽

#### Scenario: 文档页不泄露令牌

- **WHEN** 用户在文档页授权并发出请求后查看页面与网络响应
- **THEN** 令牌只出现在用户主动填写的鉴权头中，不出现在文档内容、页面其他区域或服务端响应体

### Requirement: 文档化不改变既有接口行为

补充 OpenAPI 注解与文档页面 MUST NOT 改变现有接口的鉴权、角色、班级边界、状态码或响应结构。文档端点与文档页面 MUST NOT 引入新的写操作，MUST NOT 暴露未在文档中声明的隐藏入口。

文档相关错误（文档资源缺失、文档生成异常）MUST 以可读方式返回，且 MUST NOT 影响登录、检索、问答、技能与 MCP 管理接口的正常运行。

#### Scenario: 既有接口语义保持不变

- **WHEN** 客户端调用登录、检索、问答、技能或 MCP 管理接口
- **THEN** 鉴权、状态码与响应结构与本次变更前一致

#### Scenario: 文档异常不影响业务接口

- **WHEN** 文档生成或文档静态资源加载出现异常
- **THEN** 登录、检索、问答、技能与 MCP 管理接口仍正常工作
