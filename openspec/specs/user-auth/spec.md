# user-auth Specification

## Purpose

为 CampusClaw 的教师与学生提供账号密码自助注册、加盐哈希凭据存储与基于 JWT 的登录/登出：登录成功后由服务端签发访问令牌，客户端以 Authorization: Bearer 头访问受保护 JSON 接口；未认证或令牌无效的请求一律被明确拒绝（401），前端据此引导用户登录。

## Requirements

### Requirement: 用户自助注册

系统 MUST 允许访客通过用户名、密码、角色（教师/学生）和已有班级完成自助注册。用户名 MUST 全局唯一；注册者只能选择系统中已存在的班级，不能自行创建班级。

#### Scenario: 注册成功

- **WHEN** 访客提交未被占用的用户名、符合长度要求的密码、有效角色（教师或学生）和一个已存在的班级
- **THEN** 系统创建用户记录、关联所选班级（角色与班级以表单中的合法选择为准并由服务端校验），并引导至登录页

#### Scenario: 用户名已被占用

- **WHEN** 访客使用数据库中已存在的用户名提交注册
- **THEN** 系统拒绝创建并返回明确的校验错误，且不泄露该账号的角色或班级等其他信息

#### Scenario: 选择不存在的班级

- **WHEN** 注册请求中包含系统中不存在的班级标识
- **THEN** 系统拒绝注册并返回校验错误，不创建任何用户或会话

#### Scenario: 密码不满足长度要求

- **WHEN** 访客提交的密码短于系统规定的最小长度
- **THEN** 系统拒绝注册并提示密码长度要求，不写入用户记录

### Requirement: 密码必须加盐哈希存储

系统 MUST NOT 以明文形式存储密码。持久化到数据库的 MUST 是带随机盐的哈希值；明文密码 MUST NOT 出现在数据库、应用日志、错误信息或任何接口响应中；相同密码的两个用户 MUST 得到不同的哈希值。

#### Scenario: 数据库中不存明文

- **WHEN** 任意用户完成注册后直接检查数据库中的用户记录
- **THEN** 密码字段为加盐哈希字符串（含算法标识与盐），不包含明文密码，且无法从该字段直接还原明文

#### Scenario: 相同密码产生不同哈希

- **WHEN** 两个用户使用完全相同的明文密码注册
- **THEN** 两人在数据库中的密码哈希值不同（各自使用独立随机盐），且两人后续都能各自登录成功

#### Scenario: 登录按哈希校验

- **WHEN** 用户提交密码登录
- **THEN** 系统使用哈希校验函数将提交密码与库中加盐哈希比对，而不是与任何明文比较；校验通过才建立会话

### Requirement: 账号密码登录

系统 MUST 提供账号密码登录：校验凭据通过后建立服务端会话并向浏览器写入 httpOnly 的会话 Cookie；凭据错误时拒绝登录。

#### Scenario: 使用正确凭据登录

- **WHEN** 已注册用户提交正确的用户名与密码
- **THEN** 系统建立会话、写入 httpOnly 会话 Cookie，并将用户引导到受保护首页（或登录前试图访问的页面）

#### Scenario: 使用错误凭据登录

- **WHEN** 用户提交不存在的用户名或错误的密码
- **THEN** 系统返回统一的"用户名或密码错误"提示，不区分"用户不存在"与"密码错误"，且不建立会话

### Requirement: 登出

系统 MUST 允许已登录用户结束当前会话。

#### Scenario: 用户登出

- **WHEN** 已登录用户发起登出
- **THEN** 系统清除服务端会话内容与会话 Cookie，此后携带旧 Cookie 访问受保护资源等同未认证访问

### Requirement: 受保护页面的未认证访问重定向

系统 MUST 保护登录后才能访问的页面：未认证请求不得看到任何受保护内容，MUST 被重定向到登录页。

#### Scenario: 未登录访问受保护页面

- **WHEN** 未携带有效会话的浏览器请求任意受保护页面（如材料列表页、上传页）
- **THEN** 系统返回到登录页的重定向，并记录原始目标，使登录成功后可回到原本请求的页面

#### Scenario: 登录后访问受保护页面

- **WHEN** 已登录用户请求其有权访问的受保护页面
- **THEN** 系统正常返回页面内容，不再重定向到登录页

### Requirement: 受保护接口的未认证访问拒绝

系统 MUST 对所有需要登录的服务端接口进行服务端会话校验，不得依赖前端路由或按钮隐藏作为保护手段。

#### Scenario: 未登录调用受保护接口

- **WHEN** 请求未携带有效会话 Cookie（或会话已过期、被篡改）却调用受保护接口（如上传、下载接口）
- **THEN** 系统返回 401 未授权，不执行该接口的任何业务逻辑、不返回任何业务数据

### Requirement: 会话安全与密钥管理

会话 MUST 由服务端使用仅保存在服务端环境变量中的密钥签名；会话 Cookie MUST 设置 httpOnly 并具有有效期；伪造、过期或已登出的会话 MUST 被视为无效；密钥 MUST NOT 出现在页面、接口响应或前端脚本中。

#### Scenario: 会话 Cookie 被篡改

- **WHEN** 请求携带的会话 Cookie 内容被客户端修改或签名无效
- **THEN** 系统将其视为未认证请求：页面访问重定向到登录页，接口调用返回 401

#### Scenario: 会话密钥不离开服务端

- **WHEN** 检查页面源码、接口响应、前端脚本或代码仓库中的配置
- **THEN** 均无法获得用于签名会话的真实密钥；仓库中只允许存在 `.env.example` 之类的占位说明，真实密钥只来自服务端环境变量
